Design a presentation: **$ARGUMENTS**

Work the deck through the Design Pro loop:

1. **Orient** — read `knowledge/INDEX.md`, `knowledge/01-principles/decision-framework.md`, and `knowledge/09-presentations/decks.md`. Set the format from `knowledge/08-visual-composition/format-specs.md` (default 16:9, 1920×1080; vertical only if it's a social/mobile deck).
2. **Find the through-line** — the single core message and the narrative arc. Pick the deck type (pitch/sales/conference/internal) and design accordingly (speaker-support = sparse & visual, not a leave-behind wall of text). Use the standard pitch sequence as a checklist when relevant.
3. **Design slide-by-slide** — assertion-evidence titles (the takeaway as the title, not a label), one idea per slide, big readable type (title ~40–54pt, body ~24–32pt, min ~18pt), one accent color, consistent master/grid, generous margins, direct-labeled charts. Apply the brand system (`knowledge/08-visual-composition/brand-systems.md`); derive one if none exists.
4. **Produce** — per `knowledge/13-production/production-and-tools.md`: generate an editable `.pptx`, build HTML slides → PDF, or use a slides/Express/Canva path. Keep text as real editable text. State which method and why.
5. **Self-review** against `knowledge/05-quality/review-checklist.md` and the deck-mistakes table (no text walls, no tiny fonts, no label-titles, consistent everything).

Ask only if a blocking decision is missing (audience, length, brand). Otherwise apply sensible defaults and state assumptions. Deliver the deck plus a slide outline and the production method.
